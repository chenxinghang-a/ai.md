## 算牌/EV 推理策略（老板核心要求，替代纯RL路线）
- 老板连发数条明确打牌智慧：算牌、人家大就打小(避险)、我大就直接上(留牌成大牌)、公共牌有对子/三张/能组顺子而我小就别上、预测对面牌比我大的概率→算EV→几千次对局拟合。
- 根因诊断：纯端到端RL在5万局只学到"看自己牌→出最优牌型"死记，动作空间虽有留牌能力(140=魏选2/蜀选5/吴选3)但没用 public_seen 读对手。obs 的 public_seen(52) 含公共牌+历史出牌，但网络没学会组合推理。
- 实现 `sanguopai/env/card_counter.py`：CardCounter 类。已知 我的牌+公共牌+public_seen → 剩余牌池=52−已公开−我的手牌 → 对4对手隐藏手牌做 N 次蒙特卡洛采样(对手贪心选最优牌型，能用公共牌凑葫芦) → 对每个候选动作(140)算「我赢概率」+「期望净收益EV」(复用 game 结算逻辑输赢对称cap_eff) → 选 argmax EV。可解释，非端到端RL。
- 验证(_test_counter.py)：①我小顺子+公共对9→win_prob 0.096 / EV -11.7M（打不过别上），最优改出对子(输得少)=避险✅；②手对K+公共对K→四炸 win_prob 0.996 / EV +68.6M 且最优=留牌成大牌✅。
- 接入 economy.make_cardcount_policy(n_sim=25)，四策略对照(random/greedy/trained/cardcount)。结论见下。

## 奖励塑形 + 提速（老板补充规格）
- **GPU 不可用**：当前 torch=2.13.0+cpu 无 CUDA；且瓶颈是 Python 环境模拟 + 蒙特卡洛算牌探针(hybrid 单步0.03s vs 纯RL 0.0025s，探针慢13×)，小MLP上GPU反而因搬运变慢 → 改用**多进程并行采集**真实提速。
- **奖励塑形规格(老板钉死)**：单轮算 链别人+(rank==1) / 被链−(净豆<0)；回合后算收益=净豆对称(豆子多+与豆子减−等权重, gain系数k=1)；**破产放大"豆子减−"恐惧**(负收益×(1+bankrupt_fear), 默认fear=1.0)；**破产惩罚默认=电4次(4×被链=8M)+亏1800万=2600万**；划水+(弱势win_prob<0.35且出小牌型)。默认权重 chain_others=3M/chained=2M/gain=1.0/bankrupt_fear=1.0/bankrupt=26M/paddle=1.5M，全部 argparse 可调(--rw_*)。
- **实现**：apply_shaping(reward, log_entry, agent_id, action, win_arr, shaping) 从 game.step 的 log_entry 取 rank/reward/bankrupt/剩余豆；win_arr 来自算牌器(纯RL时为None→用"输但没破产且出小牌"作划水代理)。_is_safe_action 按牌型倍率≤30判小牌。
- **train_reinforce 重构**：抽 episode_grad(weights,seed,...,shaping) 计算 REINFORCE+value+entropy 损失并 backward 返回梯度(供多进程)；train() 用 ProcessPoolExecutor(默认 min(8,cpu)，本机12核用--workers 6) 并行跑环境、平均各局梯度后 optimizer.step；--serial 回退单进程。
- **修的 bug**：① episode_grad 里 values_t 被 detach 致 value_head 无梯度→p.grad=None 崩；改为 baseline 用 detached 值、value 损失用带梯度值(标准 REINFORCE-critic)。② evaluate_vs 漏 tot+=r 致 eval 恒0。
