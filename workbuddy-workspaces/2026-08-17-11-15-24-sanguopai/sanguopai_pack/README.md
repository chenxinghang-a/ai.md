# 三国牌 · DMC 训练包 + 智能对战网页

拿去别的机器训练，再用网页看着模型变强。**本机不跑训练。**

> **计分方式默认「积分制」**：每份 `±(牌型 × 暴击 × 名次 × 杀牌)`，**无封顶、不破产**。
> 为什么不用豆子：豆制下 1800万封顶会把"打得好"和"打得差"抹成同一个数（多数局面都顶满）→ 策略差异被抹平。
> 想切回豆制（含封顶/财富档/补豆）加 `--reward chips`。详见 `RULES_AND_STRATEGY.md`「计分方式」。

> 📖 **规则与打法基准见 [`RULES_AND_STRATEGY.md`](RULES_AND_STRATEGY.md)** —— 规则以那份为唯一权威，代码与它不一致就是 bug。里面还有从结算公式推出的打法（输家三要素摆动 1536 倍、小牌型赢家反而最狠、赢不了就垫⑤、留牌判据）。

## 训练目标（就一句话）

**4 轮里让最终落袋的豆最多。** 不是"把手里的牌打出去"，也不是"选最大牌型"。摊到每轮决策，要同时算三件事：

1. **我这轮能凑出什么**：我的手牌（魏2/蜀5/吴3 张）+ 该阵营公共牌（3/0/2 张）= **5 张的组合**。牌型是**组合产物**——公共牌可能刚好帮我补成葫芦/同花，跟"我手里牌大不大"没关系。
2. **别人大概什么局面**：读他们**花掉的手牌**（不是看点数大小）→ 推他们留了什么、往哪个牌型类走；再看公共牌给了谁便宜。
3. **结算后果**：赢了当①（收豆）；**赢不了就主动垫⑤**（名次倍率只有 4），**绝不能被卡在②③④**（32/24/12）；同时避开**同类扎堆**（杀牌最高 16 倍）和**待在赢家阵营**（暴击最高 12 倍）。

而且这是**跨轮**的：这轮花掉哪几张 → 决定下轮手里剩什么、公共牌会补什么 → **"留牌"才是核心技巧**。

- 算法：**Deep Monte-Carlo (DMC)**，即开源项目 [kwai/DouZero](https://github.com/kwai/DouZero)（ICML 2021，斗地主击败 344 个 bot）的架构，适配三国牌。
- 为什么不用之前的 REINFORCE：策略梯度在「140 动作 + 4 轮信用分配 + 5 人博弈」上样本效率极低，3 万局就坍缩成「无脑选最大牌型」＝贪心，没有任何增量。
  DMC 是**价值型**：学 `Q(状态, 动作) = 这个动作最终能落袋多少豆`，逐动作打分取 argmax。它能学到**上下文相关**的风险——
  「牌大但同类扎堆会被杀牌连锁电」「当老②③④会被名次倍率打到封顶 1800万」，这些「选最大」永远看不到。
- 同族开源（想换实现）：[datamllab/rlcard](https://github.com/datamllab/rlcard) 自带 `rlcard/agents/dmc_agent/model.py` 的 `DMCModel/DMCAgent`；[google-deepmind/open_spiel](https://github.com/google-deepmind/open_spiel) 有 CFR/MCCFR/Deep CFR/NFSP。
- **★ 豆量决定策略 → 分 2 档 head**：豆子数量不是"加一个特征"就够，它**改变了 payoff 曲线形状**。
  收益上限 `U(M)=clamp(max(入场豆,当前豆),450万,1800万)`、损失上限 `D(M)=min(1800万,M)`：
  - `M ≤ 450万`：U=450万（常数）而 D=M → 风险收益比 **U/D ∈ [1,28]**，越穷越像免费彩票（16万 的人输光只亏 16万，赢一把 4 家收 1800万＝**112 倍杠杆**）→ **该激进**；
  - `M > 450万`：`U = D`，**完全对称**，还要面对名次②③④ + 暴击 12× + 杀牌 16× → **该保守**；
  所以网络是 **共享 trunk + 2 个 head**，按自己财富档路由（`tier_of` / JS `tierOf`）。一张 head 拟合两种目标只会折衷成"谁都不最优"。

## 一、在别的机器上训练

```bash
pip install -r requirements.txt
cd sanguopai_pack

# 基础跑法（6 万局，自动并行到 CPU 核数-2）
# 训练默认就是【25 人持久池随机匹配】：5 桌×5 人，豆持久、破产补 16 万
#   （真实稳态里 73% 的人压在 <50万 的地板，别用"每局重抽豆"代替，见 RULES_AND_STRATEGY.md）
python -m sanguopai.train_dmc --games 60000 --workers 8 --eval_every 2000

# 有 GPU 时（本训练器会自动用 cuda；DMC 的瓶颈在环境模拟，GPU 主要加速梯度那一步）
python -m sanguopai.train_dmc --games 300000 --workers 12 --eval_every 5000
```

产物：**只落盘"历史最好"的那份权重**（早前版本每次 eval 都覆盖写 → 落盘的可能是早已变差的最后一次）。

| 文件 | 说明 |
|---|---|
| `sanguopai_dmc_weights.json` | 权重（JSON，网页直接加载；含 `trunk.*` + `heads.0/1.*`） |
| `sanguopai_dmc_model.pt` | 权重（PyTorch，接着训用） |

常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--games` | 20000 | 训练总局数 |
| `--workers` | 0(自动) | 并行 actor 数；0=CPU核数-2，1=串行 |
| `--batch` | 512 | 一个梯度步的样本数 |
| `--buffer` | 20000 | 经验回放池上限（太大早期垃圾永久污染） |
| `--epsilon` / `--eps_start` / `--warmup_frac` | 0.05 / 0.7 / 0.15 | ε 从 0.7 退火到 0.05（**ε>0.5 期间不更新梯度**：那时数据近似随机，只烧算力还污染 buffer） |
| `--lr` | 5e-4 | RMSProp 学习率 |
| `--updates_per_game` | 2.0 | 每采集 1 局做多少梯度步 |
| `--pool_size` | 25 | 持久池人数（5 桌 × 5 人） |
| `--entry_gate` | **0（无门槛）** | **入场门槛**：低于它就离场换人。真实场次是分级的，**门槛才是"牌桌上没那么多咸鱼"的原因**——实测无门槛时 <50万 占 65.9%，门槛 1800万 时占 **0%**。按你要模拟的场设（如 `--entry_gate 4500000`） |
| `--rebuy_lo/hi` | 16万 / **160万** | 无门槛模式下破产补豆的区间（不再全员恒定 16万）。实测咸鱼占比 65.9% → **31.8%** |
| `--bust_quit` | **0.5** | **破产退出率**（退出则新玩家补位，否则补豆续命）。这是影响分布最大的参数：**0% → <50万 占 30.0%、破产 3.06 人次/局；50% → 4.6%、1.12**。0% 等价于"人人输了就充钱"（不现实，会把池子堆满咸鱼）——见 `RULES_AND_STRATEGY.md`「破产退出率」 |
| `--eval_every` / `--eval_games` | 2000 / 120 | 评估频率/局数：被测座位在 5 个位置**轮换**，其余 4 家贪心，豆表与种子固定（CRN） |
| `--starting_lo/hi` | 16万 / **2亿** | 池子初始豆的对数均匀区间。**这不是无关初值**：实测 1亿 → 池里 ≥1800万 只占 13.4%，2亿 → 31.6%（对称档样本翻倍，富档 head 才训得动）。中位数三组都恒为 16万（补豆地板），所以抬高初值只扩大"富人圈"、救不了咸鱼——见 `RULES_AND_STRATEGY.md`「咸鱼陷阱」 |

**判读日志**（积分制）：

```
[DMC] games=2000 eps=0.050 buf=... | vs贪心 净分=+8,431 rank=2.91 ②③④=48%
      偏离=31% | vs求败 净分=+41,200
```

**主判据 = 平均名次 `rank`（↓）+ ②③④占比（↓）+ 净分（↑）；`偏离` 必须配合一起读**，单看会误判：

| 偏离率 | 配合 | 含义 |
|---|---|---|
| 80%+ | 净分差、rank 差 | 未训练或训崩了（≈瞎选，不是"会躲"） |
| ≈0% | 净分平平 | 学成了"无脑选最大"= 等于贪心，没增量 |
| **20~40%** | **rank↓、②③④↓、净分↑** | **真学会躲了** —— 为名次/阵营/同类拥挤而放弃牌型大小 |
| — | `vs求败` 都不赢 | 有 bug（连"主动求败"的对手都打不过） |

> `vs求败`（`minrank`）不是强敌，是**下限校验**：它主动选最小牌型去垫⑤，连它都赢不了就说明有 bug。
> 豆制模式下日志还会多一列 `分档 rel 穷= / 非穷=`（积分制没有财富档，故不显示）。

| 指标 | 含义 | 判读 |
|---|---|---|
| `rel` | 净豆 ÷ min(自己的豆, 1800万) —— **消除财富档混淆**（净豆会被"某人豆多所以数字大"带偏，也是重尾） | **主判据，越正越好** |
| `rank` | 平均名次（1 最好） | 下降 = 会躲了 |
| `②③④` | 落在名次②③④"死亡区"（倍率 32/24/12）的比例 | **下降才是关键** |
| `bust` | 破产率 | 越低越稳 |
| 分档 rel | 穷档（≤450万）、非穷档各自的 rel | 两档分化说明"豆量决定策略"学出来了 |

参考基线（同种子 120 局，vs 4 贪心）：

| 策略 | 平均净豆 | 说明 |
|---|---|---|
| 贪心（选最大牌型） | ≈ −680万 | 起点 |
| 老 REINFORCE 模型 | ≈ −2849万 | 80% 卡在第③④名（倍率 24/12 重灾区） |
| DMC（目标） | `rel > 0` 且 `②③④` 下降才算真学到东西 | |

> 训练不需要 GPU 也能跑；`--workers` 拉满 CPU 即可。别在本机跑（按老板要求）。

## 二、网页体验（看模型"变智能"）

1. 浏览器打开 `game.html`（纯前端，无依赖）。
2. 点「加载模型权重」选训练产出的 `sanguopai_dmc_weights.json`。
3. 左侧大厅把某座位策略改成「**模型**」，其余留在「贪心」或「随机」。
4. 点「▶ 开始匹配」——5 家持久豆混着打（破产补 16 万），右侧「**模型洞察**」实时显示：
   - 该模型给 140 个动作打的 Q 值 Top10；
   - `★` = 模型所选，`◆` = 最大牌型；
   - 出现 `模型没选最大牌型：弃 X → 选 Y` 的徽章时，就是它学到的"上下文智慧"；
   - **「豆量决定策略」对比**：把**同一手牌**只改自己的豆（16万 vs 1亿），并排显示模型分别走哪个 head、各选什么动作。两种财富下打法不同（`穷人该激进、富人该保守`）就是分档 head 学出来的证据。
5. 点任意座位可看「本局结算明细」：把 `牌型 × 暴击 × 名次 × 杀牌 × 4500` 逐项拆开，看清为什么有人一把输满 1800 万。
6. 座位策略可选「我」手动出牌：**直接点牌，阵营自动定**（点 2 张→魏 / 3 张→吴 / 5 张→蜀，不用选阵营），手牌已按大小排好；选定后显示你的牌型倍率，以及**模型对这个动作的 Q 评分和它的首选**（加载权重后）。
7. 「每轮全场出牌」面板按轮列出 5 家的阵营 + 5 张牌组 + 牌型 + 名次 + 净豆——和真人牌局一样，所有人都看得见彼此出了什么。
8. 「速度」滑杆控制节奏。

**注意**：≥2 个座位同时用「模型」会明显变慢（每个决策要在浏览器里跑 140 次网络前向）。

| **赢（收款上限）** | `clamp( max(入场豆, 当前豆), 450万, 1800万 )`：带≥1800万→每份收满1800万（看**入场**豆，掉豆也照收）；带450万~1800万→入场/当前谁大用谁；带<450万→每份**只收450万**（低豆赢不大） |
| 豆不为负 | 实付不超过输家当前豆，付到 0 即停（破产） |
| 并列第一 | 每个并列第一**各收一份**（输家最坏付 k×1800万） |
| 阵营 | 魏 出2张+公共3 ｜ 蜀 出5张(无公共) ｜ 吴 出3张+公共2 → 共 140 个动作 |
| 门票 | 0（不扣）｜ 破产补豆 16万，局间续打 |
| 牌 | 52 张，`code = suit*13 + rank`，A 可作 1 或最大、2 最小；4 轮牌循环 |

## 四、已验证的工程一致性（别改坏）

为保证"训练出来的模型在网页里表现一致"，以下两条做过**逐位校验**：

- **特征编码**：`train_dmc.py` 的 `build_action_feats/build_state_feats` 与 `game.html` 的 JS 版本，
  `S_DIM=706 / A_DIM=45 / IN_DIM=751`，140×45 动作特征 + 706 维状态特征 **max diff = 0**（含 512 维历史块，见下）。
- **网络前向**：`QNet`（共享 trunk 256×3 + **2 个 head**，按财富档路由）Python vs JS：**每个 head 都 max diff ≈ 1e-8，argmax 相同**。
- 加载权重时网页会**校验输入维度**：不匹配（例如旧版 735 维 json）会直接报警告而不是静默错位出垃圾 Q。

> 改任何一侧的编码，必须重跑这两个校验，否则网页里的模型会"变笨"。

### 状态编码明细（706 维 = 基础 194 + 历史块 512）
| 段 | 维度 | 含义 |
|---|---|---|
| 我的手牌 | 52 | 我 8 张牌的 one-hot |
| 公共牌 | 52 | 魏3 + 吴2 的 one-hot |
| 出现过的牌 | 52 | 历史上露过面的牌（弱信号：本局出过的牌会回库循环） |
| 轮次 | 4 | one-hot |
| 我的豆 | 2 | log 尺度的 + 线性归一 |
| **我的财富档** | **2** | **≤450万（高杠杆，该激进）/ >450万（对称，该保守）——决定用哪个 head** |
| **破产距离 + 本局盈亏** | 1 + 1 | 还能吃几份自己的封顶 ／ (当前豆−入场豆)/入场豆 |
| 各阵营最强牌型 | 3 | 我拿魏/蜀/吴分别能凑到的最强牌型（归一） |
| 对手豆、对手入场豆 | 4 + 4 | 4 个对手各自归一（对数尺度） |
| **对手收款档** | **12** | 每个对手 3 档：他当赢家时能从我这儿收多少 |
| **我 vs 对手（最大/平均）、对手穷人比例** | 2 + 1 | "我是不是桌上那个肥羊/穷鬼" |
| 存活数、牌库 | 1 + 1 | |
| **历史块** | **512** | **每轮(4) × 每个对手(4) × 32** = 阵营(3) + 他花掉的手牌点数(13) + 牌型(9) + **名次(5)** + **被结算多少(1)** + **是否破产(1)** |

**历史块 = 读对手的「留牌」**。⚠️ 注意：**不是**看他打出的 5 张牌的点数大小——牌型是「手牌 + 公共牌」拼出来的**组合产物**：人家手里两张小的，公共牌刚好补个葫芦，看着就"大"了，**点数本身没有信息量**。

有信息量的是：**他愿意花掉手里哪几张**（公共牌那部分要剔掉——公共牌是公用的，不算他的信息）→ 由此推他留了什么、下轮能凑什么、正往哪个牌型类走（杀牌同类拥挤）。

### 动作编码明细（45 维）
阵营 one-hot(3) + 用了哪几张手牌(8) + 5 张牌的点数计数(13) + 花色计数(4) + 牌型 one-hot(9) + **杀牌类 one-hot(6)** + 牌型倍率归一(1) + tiebreak 强度(1)。
