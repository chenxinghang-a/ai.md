## 二、中等与轻微

6 路合计另有约 **56 条**中等/轻微问题，集中在：

- **异常路径只记日志就往下走**（导致后续步骤基于错误假设执行）
- **查了某个字段却从不判断它的值**（死条件）
- **无界缓存 / 只增不删的字典**（长期运行 OOM）
- **共享可变状态缺锁**（并发路径）
- **边界**：除零、空集合、`None` 参与数值比较
- **WebSocket 事件处理器对畸形 payload 无防护**

## 三、这批 bug 为什么能活过 2067 个测试

审计同时查清了**测试为什么拦不住**：

| 机制 | 影响 |
|---|---|
| `tests/conftest.py` 把 `auth_manager` 换成 MagicMock 且 `verify_token` **默认返回真值** | **217 个依赖 `auth_headers` 的测试，鉴权断言全是空断言** —— 删掉鉴权装饰器它们照样绿 |
| `database` 也是 MagicMock | **「数据没真的落库」这类 bug 物理上不可能被检出**（本轮 `insert_data_batch` 变异为「什么都不写」，测试仍全绿） |
| `conftest.py` 建**裸 Flask app**，不走 `create_app()` | 只有 `create_app()` 才执行的路径（限流绑定、请求去重、安全响应头、蓝图注册顺序）**永远不被覆盖** |
| 大量 `assert x is not None` 式弱断言 | 只证明「调用没抛异常」，不证明行为正确 |

**结论：这 2067 个绿点证明的是「代码能跑完不崩」，不能证明「代码做了它该做的事」。**

## 四、建议修复顺序

1. **先修数据丢失与漏报**（#1 删 23 天数据 / #8 报警不响 / #2 熔断死代码 / #3 假数据入库）
   —— 这四条直接影响生产安全
2. **再修安全与越权**（#10 写校验失效 / #11 健康检查谎报 / #12 幂等假成功）
3. **再修高可用**（#13 备机不接管 / #14 指令未执行）
4. **最后批量处理中等/轻微**
5. **同步修测试底座**：至少让鉴权与落库走真实对象，否则修完仍无法验证
