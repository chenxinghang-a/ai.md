## 一、零删除根治（核心诉求）

### 1.1 问题本质

之前一直在用**错误的方法**打补丁：把 `delete` 换成 `rename`。
那只是把弹窗从"删"挪到"改名"，**弹得更频繁**，且留下一堆 `.prev*` / `.trash` 目录。

正确路线：**让这些操作根本不产生待删文件**。

### 1.2 逐工具改造

| 触发点 | 原做法（永远弹窗） | 改后（零删除） | 文件 |
|---|---|---|---|
| pytest 临时目录 | 系统 TEMP 下滚动清理旧 run（上万文件） | basetemp 指向仓库内 `.pytest_tmp-<pid>`，**每 run 唯一** | `tests/conftest.py` |
| pytest 缓存 | 写 `.pytest_cache/v/cache/*` | `-p no:cacheprovider` | `pyproject.toml` |
| PyInstaller | `shutil.rmtree('dist')` + `rmtree('build')` | `--distpath dist-scada-<ver>` / `--workpath build-scada-<ver>` | `build.py` |
| vitest 缓存 | 默认位置 | `cacheDir: '.vitest_cache'` | `vitest.config.ts` |
| electron-builder | 无 `--publish never`（CI 会失败） | 加 `--publish never` | `package.json` |

### 1.3 ⚠️ 中途踩的坑（关键，已写进 skill）

**第一版把 basetemp 写死成 `.pytest_tmp`（固定路径）→ 整套测试在 setup 阶段全 ERROR：**

```
[safe-delete][SAFE_DELETE_FAIL_CLOSED] {"target": "...\\.pytest_tmp", "reason": "trash-failed"}
OSError: [Errno 53] 找不到网络路径。: '\\?\C:\...\industrial_scada\.pytest_tmp'
```

**根因**：pytest 会话开始时若发现 basetemp 已存在，会**先清空它**。走 shim 的
"移回收站"路径时，对 `\\?\` 前缀路径报 `Errno 53` → fail-closed 拒绝。

**正解**：basetemp 目录名带 **PID**，保证每次进程启动时都是**全新的、不存在的**路径
→ pytest 无需清任何东西。实现在 `tests/conftest.py` 的 `pytest_configure`。

## 二、质量码链路打通（P1 契约缺口）

### 2.1 缺口全貌：三处断裂

`Dashboard.vue` 有一套完整的 OPC UA 质量码 UI（彩色圆点 + Good/Uncertain/Bad 三档，
阈值 192/64），但**数据源全是死的**：

| 环节 | 修复前 | 修复后 |
|---|---|---|
| ① SQLite 表 | `realtime_data` **无 quality 列** | 加 `quality INTEGER DEFAULT 192` + 迁移 |
| ② 写入 | `valid_rows` 只取 5 字段，**整个丢弃** | 持久化 quality + UPSERT 时更新 |
| ③ 轮询 | `loadData()` 只填 `deviceValues`/`registerUnits` | 补填 `deviceQuality` |
| ④ WS 推送 | 载荷来自 DB 行，自然无 quality | 自动带上 |
| ⑤ 前端类型 | `quality: string`（类型撒谎） | `number \| null` + `normalizeQuality()` 收敛 |

**连锁影响**（修复前）：`quality == null && bar` 恒为真 → 永远走"用报警阈值补语义色"
的降级分支 → 质量码 UI 是纯粹的装饰品。

### 2.2 旧库迁移（易漏点）

`CREATE TABLE IF NOT EXISTS` 对**已存在的表是空操作** → 光改建表语句对生产库无效。
新增 `_migrate_realtime_quality()` 走 `ALTER TABLE ADD COLUMN`，
存量行得默认值 192(GOOD)（无法追溯真实质量，宁可显示"好"也不要凭空报"坏"引发无谓告警）。

### 2.3 防字符串污染

后端历史上**同时存在三种 quality 语义**：
- 采集层 OPC UA 数值码（192/104/0/4/6/8/80/64，int）
- 模拟客户端字符串标记（`'good'` / `'simulated'` / `'BAD'`）
- OEE 接口的 `quality` 是 0~1 **质量率**（同名不同义）

直接比较会让 `'BAD' >= 192` 求值为 false → **静默判成 Bad 且不报错**。
新增 `normalizeQuality()`：只接受有限数值，非数值一律 null（走安全的降级分支）。

### 2.4 `getLatest` 返回形态

后端该接口有**两种形态**（`api_data.py:50-59` → `database.py:472-517`）：
- 不传 `register_name` → `{寄存器名: {...}}` 映射
- 传了 → **单条平铺 dict**

原类型统一声明 `Record<string, LatestValue>` 是对第二种形态的撒谎。
改为两个**精确方法** `getLatestLatestMap` / `getLatestSingle` + 保留联合类型兼容入口。
